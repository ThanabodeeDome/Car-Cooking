# เครื่องมือวัดความแม่นของ OCR เลขไมล์

ใช้วัดว่า `Car/ocr_odometer.php` อ่านเลขไมล์จากรูปหน้าปัดถูกกี่ % **ก่อนและหลังแก้โค้ด**
(เคยแก้แล้วเกิดบั๊กซ้อนมา 2 รอบเพราะไม่มีตัววัด — commit `3edae5e` แล้วต้องตามแก้ด้วย `1cfe46c`)

## วัดกับรูปจริง

```
php tools/ocr/bench.php tools/ocr/truth_nohint.csv   # ไม่ส่งไมล์ตอนออกไปช่วย (เคสแย่สุด)
php tools/ocr/bench.php tools/ocr/truth_hint.csv     # ส่งไมล์ตอนออกไปช่วย (เคสปกติในระบบ)
```

- จำลอง pipeline เดียวกับหน้าเว็บจริง: ย่อด้านยาวสุดเหลือ 1000px + JPEG q80 (ตาม `Car/return_scan.js`)
- ดึงฟังก์ชัน `odometerDecide()` / `odometerCandidates()` **ตัวจริง** จาก `Car/ocr_odometer.php`
  มา eval (ไม่ได้ก๊อปโค้ดมาไว้ที่นี่) แก้โค้ดจริงแล้ววัดซ้ำได้เลย
- ข้อความดิบจาก OCR.space ถูก cache ไว้ใน `raw_cache.json` ต่อ (รูป + engine)
  **รันซ้ำกี่รอบก็ไม่กินโควตา API** จะเรียกจริงเฉพาะรูปที่ยังไม่เคยเจอ

## เทสกันบั๊กเก่ากลับมา (ไม่เรียก API เลย)

```
php tools/ocr/regress.php
```

ใส่ข้อความ OCR จำลองของเคสที่เคยพังมาแล้ว (เลขถูกตัดคนละบรรทัด, ตัวคั่นหลักพัน,
นาฬิกา/วันที่, trip มีทศนิยม, ในรูปมีแต่ขีดสเกล) — ควรขึ้น "ผ่านหมด" ทุกครั้งก่อน commit

## ไฟล์เฉลย (truth csv)

```
ไฟล์รูป,เลขไมล์จริง,ไมล์ตอนออก
Car/uploads/return/xxx.jpg,123073,122950
Car/uploads/return/yyy.jpg,-,-            # "-" = ในรูปไม่มีเลข ODO -> ถูกเมื่อระบบไม่เดา
```

เลขไมล์จริงต้องเปิดรูปดูด้วยตาแล้วกรอกเอง ห้ามเอาค่าที่ระบบอ่านได้มาเป็นเฉลย

> รูปในชุดทดสอบตอนนี้วางอยู่ที่ `Car/uploads/return/` (ไม่ได้ commit เข้า git)
> ถ้าจะเก็บเป็นชุดถาวรควรย้ายมาไว้ใน `tools/ocr/fixtures/` แล้วแก้ path ใน csv
